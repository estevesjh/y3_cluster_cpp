FINDINGS SURFACED WHILE WRITING THESE (recorded, not fixed)
------------------------------------------------------------
 F1  biasModel.bias_at_M is DEAD CODE in BOTH copies
     (cosmology/halo_model.py ~line 150, y3_buzzard/haloModel.py ~line 115):
     calls self.compute_nu(M) — no such method — then passes odelta= to a
     one-arg bias_at_nu. Any call raises AttributeError. Nothing is
     miscomputed today (production uses nu_at_M + bias_at_nu directly).
     Pinned as a characterization test that goes RED when fixed.

 F2  [FIXED in working tree, NOT yet committed] Both sel_kernels shims
     cached under the SAME sys.modules key "y3_des_sel_function". In a
     process that imports both, whichever load() ran FIRST won and the
     second silently got the other copy. Survivable only because the two
     sel_function copies are numerically identical — which is exactly what
     dual_copy_identity_test pins.
     Keys are now ..._shared / ..._systematics. The characterization test
     went red on the fix (as designed) and has been replaced with a
     positive one. Pending commit:
       src/pipelines/shared/sel_kernels.py
       src/pipelines/systematics/selection_richness/python/sel_kernels.py
       test/dual_copy_identity.test.py

 F3  ShearPrjGl's rnd AND cl channels are NEGATIVE on a small-R wall.
     Not a defect: the projection branch uses the SINGLE (delta-offset)
     kernel, whose signed DSigma_mis has a negative lobe for R << R_off,
     and the theta integral runs to R_max = 35 Mpc/h. Documented in the
     test so nobody "fixes" it later.

 F4  |cl| is NOT monotone in the richness-bin centre lob: lob moves the
     exclusion, the theta breakpoints and the b_sel(theta) profile at once
     and in opposite directions (measured: at R = 0.5 raising lob lowers
     |cl|, at R = 1.5 it raises it). An "exclusion always reduces cl" test
     would have pinned an artefact of one radius. Used R_max_cMpch as the
     clean single-knob handle instead.

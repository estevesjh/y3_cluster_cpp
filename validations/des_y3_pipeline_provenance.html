2.1 · Canonical observables — production module family (des_y3_cpp0d_fast_apriori.ini)

The rows above validate the new src/pipelines/des_y3 stand-in modules (NumCountsSijGl, Shear1hGl, ShearPrjGl/ShearPrjCuhre). The rows below instead validate Nij, ΔΣij1h, ΔΣijprj, and the max(1h,2h) model using the actual production module names as wired in cosmosis-models/des_y3_cpp0d_fast_apriori.ini — NumCountsSel, DSigma1hSel (both src/modules/num_counts_sel/, legacy production, pre-dating src/pipelines/des_y3), sigma_prj/dsigma_prj/shear_prj (ShearPrjEvaluator.so, src/modules/sigma_prj_cpu/ — same sp_detail::ShearPrjCore physics as ShearPrjGl, different module wrapper), and Shear1h2hMax (src/pipelines/des_y3/shear_1h2h/cpp/0d). Run pair: smoke_full_sel_cp_camb.ini (cp_camb) vs smoke_sel_camb.ini (real CAMB, nonlinear = both) for the first three; a new CAMB-truth companion, real_pipeline_extract_max2h_camb.ini, built this session (mirroring the physics_validation_pipelines.ini → physics_validation_camb.ini swap pattern) for the max model — both run without the CUDA-only Shear1h2hMaxGpu module, which isn't built on this CPU-only tree.

smoke_full_sel_cp_camb.ini as committed fails (cp_camb.py requires sigma8, the values file only carries log1e10As; the s8 emulator .npz paths also need pointing at the _s8_ variants, and CAMB_EMULATOR_DIR needs to be on PYTHONPATH for cp_numpy to import) — run here with -p cp_camb.linear_pk_path=... cp_camb.linear_nonu_pk_path=... and -v cosmological_parameters.sigma8=0.8238 (same widePlanck point used throughout this document), a staleness worth fixing separately from the projection-term finding above.

Apples-to-apples fix baked into the run pair: the pipeline’s ξ_NL is built from linear P(k) (issue #9, xi_nl_linear_fallback.md), so the CAMB companion sets nonlinear = none. Before this fix the ΔΣ_prj “pure-emulator” residuals read 15% median — they were measuring missing halofit, not the emulator. After: 0.02% median.

What the tests found

Four things surfaced while writing them. None is fixed here — two are recorded as characterization tests that go red when someone repairs them, and two are documented so nobody "fixes" correct behaviour.

F1 · DEAD CODE · both copies · still open

biasModel.bias_at_M can never have run

It calls self.compute_nu(M) — no such method; the real one is nu_at_M — and then passes odelta= to a one-argument bias_at_nu. Present identically in cosmology/halo_model.py and y3_buzzard/haloModel.py. Nothing is miscomputed today: production reaches halo bias through nu_at_M + bias_at_nu directly. It is a trap for the next caller, so the current AttributeError is pinned.

F2 · FIXED in the working tree

Both sel_kernels shims cached under one sys.modules key

Each used the name y3_des_sel_function. In a process that imports both — the production module imports the shared shim while the tests import the systematics one — whichever called load() first won, and the second silently received the other copy. Survivable only because the two sel_function copies are numerically identical, which is exactly what the identity test alongside it guarantees.

The keys are now distinct (…_shared / …_systematics). The characterization test did its job — it went red the moment the fix landed — and has been replaced by a positive one asserting the keys are separate, both modules coexist, and caching still works. Not yet committed.

F3 · NOT A DEFECT

ShearPrjGl's rnd and cl channels are negative at small R

The projection branch uses the single delta-offset miscentering kernel, whose signed ΔΣmis has a negative lobe wherever R ≪ R_off — and the θ integral runs out to R_max = 35 Mpc/h, so almost every (θ, M) node contributes from that lobe. Documented in the test so the sign is not later "corrected".

F4 · TEST DESIGN

|cl| is not monotone in the richness-bin centre

Raising lob moves the slab exclusion, the θ breakpoints and the b_sel(θ) profile at once and in opposite directions: at R = 0.5 it lowers |cl|, at R = 1.5 it raises it. An "exclusion always reduces cl" assertion would have pinned an artifact of one radius. R_max_cMpch is used instead — it moves only the outermost θ breakpoint, so the added contribution is strictly negative and the invariant holds signed.

Caveats on the numbers

  • The coverage tables are measured, on this tree, today. Instrumented Debug build, full ctest run, gcovr 8.5 through llvm-cov gcov. Nothing is estimated or adjusted upward on the strength of a test existing.
  • Cross-run comparison is directional only. The "Prev." column is a gcc Release build on NERSC; this is a clang Debug build. Same source, different instrumented-line denominators — so 0% → 99% is real and 89.7% → 81.8% is an artifact of the change in denominator.
  • Line, not branch. Branch coverage is 7.2% tree-wide; the tables use line hits, the fairer metric for header-heavy template code.
  • CPU-only. USE_CUDA=Off, so all .cu/.cuh device code and the 12 CUDA tests are outside these numbers entirely.
  • Python percentages still don't exist. The Python table is a static import map, verified by reading each test's imports.
  • Passing ≠ covered remains true, and shear1h2h_max_test was the worked example — green in ctest, 0% on the header it names. It is now joined by a test that does instantiate the header, rather than being replaced by one.
  • The new tests assert invariants, not accuracy. No number here is a fiducial prediction. Agreement with the adaptive reference is the job of the validate_*.py harnesses against real dumps; these are structural, algebraic and contract checks that hold for any input.
  • Validators (validate_*.py) are accuracy harnesses run manually against fiducial dumps; they are counted here as validators, not unit tests.
